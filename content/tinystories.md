## 7.2 TinyStories

首先使用很简单的 TinyStories 数据 [1]，模型训练较快，也能观察有趣现象。获取方式见第 1 节。

::: example tinystories_example | TinyStories 数据样例

从前，有个叫 Ben 的小男孩，喜欢探索周围的世界。他见过很多奇妙的东西，比如商店里陈列的漂亮花瓶。一天，他在店里发现了一个很特别的花瓶，惊叹道：“哇，这个花瓶真漂亮！我可以买它吗？”店主微笑着说：“当然！你可以带回家，让朋友们看看它有多棒！”Ben 骄傲地把花瓶带回家，叫来朋友们展示。大家都觉得它很漂亮，不敢相信 Ben 这么幸运。这就是 Ben 在商店里找到一个漂亮花瓶的故事！

*以上为语料示例的中文翻译；实际数据仍是英文。英文原文保留在本页末尾。*

:::

### 7.2.1 超参数调优

下面给出一些起点；其他配置需要你寻找有效取值。

| 超参数 | 起始值与说明 |
| --- | --- |
| 词表大小 | **10,000**。常见词表为几万至几十万，可以尝试变化并观察词表与模型行为。 |
| 上下文长度 | **256**。TinyStories 可能不需要长序列，后面的 OpenWebText 可以尝试不同长度，观察每步时间与最终困惑度。 |
| <code>d_model</code> | **512**，小于许多小型 Transformer 论文使用的 768，有助于提速。 |
| <code>d_ff</code> | **1344**，约为 $\frac83d_{\mathrm{model}}$，且为 64 的倍数。 |
| RoPE 的 $\Theta$ | **10,000**。 |
| 层数、头数 | **4 层、16 头**，约 17M 非嵌入参数，属于很小的 Transformer。 |
| 总处理 token 数 | **327,680,000**；批次大小 × 总步数 × 上下文长度应大致等于它。 |

还需要试验：学习率、学习率预热、AdamW 的 $\beta_1,\beta_2,\varepsilon$、权重衰减。典型配置可参考 Kingma 等人 [22]。

### 7.2.2 组合起来

准备好已训练的 BPE，编码训练数据，再用自己的训练循环运行。

**原文性能参考：** 正确且高效的实现，采用上述配置，在一张 B200 上约需 **20–30 分钟**。如果明显更慢，检查数据加载、检查点、验证损失是否成为瓶颈，以及运算是否正确批处理。

### 7.2.3 调试模型架构的技巧

建议熟悉 IDE 内置调试器，如 VSCode、Zed 的调试器，比大量打印更省时间。使用文本编辑器时可以考虑 ipdb。

- 开发神经网络常先在单个小批次上过拟合；实现正确时，应该能较快把训练损失降到接近零。
- 在不同组件中设置断点，检查中间张量形状是否符合预期。
- 监测激活、权重、梯度范数，确认没有爆炸或消失。

::: problem learning_rate | 调整学习率 | 3 | 2 B200 小时

学习率是最重要的超参数之一。以已训练的基础模型为起点，完成：

**(a)** 对学习率做超参数扫描，报告最终损失；若发散则注明。

**交付物：** 多个学习率对应的学习曲线，并解释搜索策略。

**交付物：** TinyStories 每 token 验证损失**不高于 1.45** 的模型。

**(b)** 常见经验认为最佳学习率位于“稳定性的边缘”。研究开始发散的学习率与最佳学习率之间的关系。

**交付物：** 随学习率增大的学习曲线，至少包含一次发散运行，并分析它与收敛速度的关系。

:::

::: tip 低资源提示：在 CPU 或 Apple Silicon 上训练

如果在 <code>cpu</code> 或 <code>mps</code> 上运行，可将总处理 token 数降到约 **40,000,000**，验证损失目标从 1.45 放宽到 **2.00**。这已足以生成相对流畅的文本。

课程参考实现在 M4 Max、36 GB 内存上采用：

$$
32\times5000\times256=40,960,000\ \text{tokens}
$$

CPU 耗时 **1 小时 22 分钟**，MPS 耗时 **36 分钟**；第 5000 步验证损失为 **1.80**。

原文补充建议：

- 若总共训练 $N$ 步，把余弦学习率的退火终点设在第 $N$ 步，使其恰好达到最小学习率。
- 在 MPS 上不要像 CUDA 那样启用 TF32，即不要设置 <code>torch.set_float32_matmul_precision('high')</code>。课程在 **PyTorch 2.9.0** 上观察到 MPS 后端可能静默使用错误内核，造成训练不稳。
- 可用 <code>torch.compile</code> 加速。在 CPU 上使用默认编译；MPS 可使用 <code>backend="aot_eager"</code> 适度优化反向传播。原文指出，截至 **PyTorch 2.9.0**，MPS 不支持 Inductor 编译。

这些是 v26.0.3 指导书记录的版本特定现象，阅读时应结合自己的运行环境。

:::

### 批次大小

较大批次可通过更大的矩阵乘法提高 GPU 效率，但是否总是越大越好？接下来用实验观察。

::: problem batch_size_experiment | 改变批次大小 | 1 | 1 B200 小时

将批次大小从 **1** 一直变化到 GPU 显存上限。至少尝试若干中间值，包括 **64、128** 等典型值。

**交付物：** 不同批次大小的学习曲线，必要时重新优化学习率。

**交付物：** 用几句话讨论批次大小对训练的影响。

:::

### 生成文本

现在使用解码器检查模型生成质量。至少应达到下列原文样例的水平。

::: example ts_generate_example | TinyStories 语言模型的生成示例

从前，有个漂亮女孩叫 Lily。她喜欢吃口香糖，尤其是那块大的黑色口香糖。一天，妈妈请她帮忙做晚饭。Lily 很兴奋，因为她喜欢帮妈妈。妈妈煮了一大锅汤，Lily 开心地说：“谢谢妈妈！我爱你。”她帮妈妈把汤倒进大碗里。晚饭后，妈妈又做了一些美味的汤。Lily 很喜欢，说：“谢谢妈妈！这汤真好喝！”妈妈笑着说：“你喜欢就好，Lily。”她们做完饭，又继续一起做饭。故事结束。

*译文保留了原示例的重复和情节不连贯之处；模型实际生成的是英文。*

:::

‘嘿，Polly！我们出去吧！’Tim 说。Sue 看着天空，发现很难找到一种跳舞闪耀的方法。她笑了，同意帮助说话！

Sue 看着天空移动，那个是什么。她”

对应英文样例保留在本页原文中。
